# Recording-Driven Contact Manipulation

## Goal

Upgrade MORPH's human-video replay so personally recorded demonstrations control a Panda arm through a real MuJoCo contact task. The task should approximate picking up the small package from the tabletop and placing it in the wooden bowl. Add a learned, action-conditioned dynamics model (world model) trained on MuJoCo transitions generated by replaying those personal demonstrations. Report physical task outcomes and world-model prediction fidelity.

## Constraints and scope

- Use the existing 16 locally collected overhead videos: 12 human-labeled successful attempts and 4 failed attempts.
- Retain MediaPipe palm tracking and per-video workspace marker calibration. The recorded XY hand path must determine the Panda's motion.
- Add inferred manipulation phases because monocular overhead video has no metric Z and no gripper-state labels.
- Model a compact package as a rigid rectangular box and the bowl as a shallow, open receiving tray. Make clear these are simulation proxies.
- Use MuJoCo contact dynamics. Never teleport, weld, or kinematically attach the object to the gripper.
- Define robot success from object lift, release inside the receiving region, stable table/tray contact, and converged IK.
- Keep raw videos, task-layout coordinates, tracking CSVs, calibration data, per-clip trajectories, and logs outside Git. Only aggregate, non-identifying metrics and a generated plot may be committed.
- Do not claim a trained VLA, learned manipulation policy, physical robot validation, or sim-to-real performance.
- The ML contribution in this milestone is the state-based world model below; it is not a VLA or a learned manipulation policy.

## Design

### Task layout

Add a small local JSON layout that stores pickup and dropoff points in the normalized, rectified workspace coordinate system. One layout is shared across this fixed-camera recording batch. The evaluator transforms these points through each clip's own calibration and configures the package start position and tray center. The JSON is supplied by the user and is never written into the repository by a processing command.

### Demonstration-conditioned controller

Retarget the tracked palm CSV to calibrated workspace XY and preserve its timestamps. Follow the observed XY path at an approach height. When the end effector enters the configured pickup radius, descend to grasp height, close the Panda gripper, and lift. Continue following the recorded XY path at carry height. When it enters the dropoff radius, descend, open the gripper, and retreat. A clip that never triggers a phase remains an unsuccessful robot attempt; do not synthesize a missing human action.

Use explicit configurable heights and radii with conservative defaults. The controller logs state transitions, gripper commands, object pose, table/tray contacts, and IK convergence. Each clip gets a fresh simulation initialized from the same seed.

### Physical task and evaluation

Extend the existing manipulation scene with a compact box proxy and a shallow receiving tray with collision geometry. Keep the oracle cube experiment unchanged. A simulated attempt succeeds only if the box rises at least 5 cm above its initial center, is released inside the tray footprint at its resting height, remains supported and stable, and all required IK samples converge.

Run both retargeting methods on all 16 clips. Save per-clip results locally. Commit only aggregate totals, success rate by human label, a human-label versus simulation-outcome confusion matrix, and a plot. Include a local paired video showing a real clip and its physics-based Panda replay.

### Learned dynamics model

Add an optional PyTorch component in a separate environment so the existing MuJoCo/video install stays lightweight. Define simulation state as Panda end-effector position and arm joint positions, package position and linear velocity, gripper opening, and package/gripper and package/support contact flags. Define action as the Cartesian target and gripper command sent to the contact controller. The model predicts the next state delta at the fixed MuJoCo control interval.

The ordered state vector is `[ee_xyz(3), arm_qpos(7), package_xyz(3), package_linear_velocity(3), gripper_aperture(1), package_gripper_contact(1), package_support_contact(1)]` (19 values). The action is `[cartesian_target_xyz(3), gripper_aperture_target(1)]` (4 values). Train a two-hidden-layer MLP with 128 units per layer to predict the normalized next-state delta. Split whole clips for validation so adjacent frames from one recording never leak across train and validation. Compare one-step and 0.5-second rollout error against MuJoCo ground truth and a persistence baseline (`next_state = current_state`). Save checkpoints, transition data, and per-clip predictions locally; commit only aggregate prediction errors and the model definition/training command.

### Failure handling

Reject malformed layouts, out-of-workspace task points, missing calibrations, unusable trajectories, and output paths inside the repository before writing personal files. If the robot does not reach a phase trigger or physically fails to carry the box, log the failure reason and continue with the next clip.

## Acceptance criteria

1. Synthetic path tests prove the gripper closes at the pickup region, stays closed while carrying, and opens only at the dropoff region.
2. A physics test proves a box can be lifted and stably deposited in the receiving tray without teleportation.
3. A deterministic test proves each clip starts from an independent identical reset state.
4. The 16-video batch produces a result for every clip and both methods; failures remain in the aggregate denominator.
5. The world-model test learns from generated local transitions and reports held-out one-step and 0.5-second prediction errors against persistence.
6. Aggregate data separates human labels from robot outcomes and contains no per-clip paths, frames, coordinates, or checkpoints.
7. README commands reproduce the local task-layout setup, evaluation, world-model training, and paired demo. Limits distinguish proxy geometry and assumed 2D-to-robot calibration from physical validation.
